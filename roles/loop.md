# 角色闭环协议（Supervision Loop）

> 定义「监督角色 ↔ 开发角色」的协作闭环。目标是让复刻产物与原版 WorkBuddy 在当前阶段范围内保持一致，不一致就循环修复，直到一致。

## 角色与文件

| 角色 | 职责 | 拥有的文件 |
|---|---|---|
| 监督角色（Supervisor） | 对比基线、出差异报告、复检、裁定终止 | `spec/original-baseline.md`（基准）、`spec/parity-gaps.md`（差异） |
| 开发角色（Developer） | 读差异、改代码、回写状态 | `src/**`、`package.json` 等 + 回写 `parity-gaps.md` 状态 |

角色定义见 `roles/supervisor.md` 与 `roles/developer.md`。

## 闭环流程

```
        ┌─────────────────────────────────────────────┐
        │                                               │
        ▼                                               │
  ┌───────────┐   差异清单    ┌───────────┐  修复+回写  │
  │ 监督角色   │ ───────────► │ 开发角色   │ ────────────┤
  │ 出报告     │              │ 逐条修复   │             │
  └───────────┘              └───────────┘             │
        ▲                            │                 │
        │         复检（不通过回退）    │                 │
        └────────────────────────────┘                 │
                     │                                  │
                     │ 复检通过 / 清零                    │
                     ▼                                  │
              ┌───────────┐                            │
              │ 循环终止    │ ───────────────────────────┘
              └───────────┘
```

## 状态机

每条差异（GAP）状态流转：

```
open ──开发角色修复──► resolved ──监督复检通过──► closed（关单）
  ▲                        │
  │                        └──监督复检不通过──► open（回退）
  │
  └── 明确暂缓 ──► deferred（不阻塞终止判定）
```

- `open`：待开发角色处理。
- `resolved`：开发角色已改，待监督复检。
- `closed`：监督复检通过，从活跃清单移除（保留在历史）。
- `deferred`：当前阶段明确不做，不阻塞「循环终止」判定。

## 循环终止条件

同时满足：

1. 不存在 `open` 或 `resolved` 的 P0/P1 差异；
2. P2 差异为 `closed` 或 `deferred`。

## 每轮监督的输出

监督角色每轮必须在 `parity-gaps.md` 末尾给出：

```markdown
> 闭环状态：剩余 N 条 open 差异。→ 开发角色  /  已清零，终止。
```

## 变更范围守护

- 监督角色只改 `spec/` 下的基线与差异文件。
- 开发角色只改 `src/` 与 `package.json` 等源码，以及回写差异状态。
- 任何一方要扩大「复刻范围」或「暂缓」某项，必须通过修改 `original-baseline.md` §7 范围共识 + 在差异报告中注明，而不是口头降级。
